Ruta verificable para la primera capa del microservicio real de Catalog

Fecha de preparación: 14 de octubre de 2026 · Alcance activo: Catalog + Sales

1. Resumen ejecutivo

El proyecto parte del baseline integrado de Brandow y organiza el siguiente paso: separar Catalog como proceso Python independiente, con MongoDB propio, contrato HTTP versionado y pruebas TDD. Sales/API general ya puede consumir esa frontera mediante CATALOG_SERVICE_URL. La entrega demuestra una primera capa ejecutable; no afirma todavía un cutover productivo.

60% verificadoAlcance, registry, arquitectura, TDD, contrato y boundary de Sales.
Catalog aisladoDocker + MongoDB + health live/ready en puerto 8082.
Siguiente gateAtomicidad, idempotencia, E2E y retiro controlado del legacy.

3. Trayectoria secuencial

  1. Congelar el registry dinámico y el ownership de Catalog.
  2. Levantar MongoDB y el contenedor Python sin el monolito.
  3. Ejecutar TDD, compilación de sintaxis y validación de Compose.
  4. Verificar health, correlación, consulta, reserva y liberación con fixture controlado.
  5. Validar que Sales use HTTP mediante CATALOG_SERVICE_URL y nunca lea catalog_db.
  6. Publicar el PR como primera capa, con límites explícitos.
  7. Implementar después atomicidad/idempotencia, Saga/Outbox, E2E y cutover.
